# DBMLFF Tutorial: Building Force Field for EC Molecule

## Overview
This tutorial provides a complete guide to building the Density-Based Machine Learning Force Field (DBMLFF) for EC (ethylene carbonate) molecules. The working directory is `example_EC/train`. The same workflow applies to building DBMLFF for other molecules. The DBMLFF framework consists of three key components: MLFF, DB, and POL, which collectively describe molecular interactions with high accuracy and computational efficiency.


### 3. MLFF Component: Linear Model for DFT-DB Differences
**Working Directory:** `train/MLFF`

#### 3.1 AIMD Data Preparation
**Multi-molecule System:**
- Build initial model with 15 EC molecules at experimental density
- AIMD: 400K, 700K, 1200K (5000 steps, 0.5 fs, NVT ensemble)

**Monomer Simulations:**
- 3 random EC molecules
- Single-molecule AIMD: 400K_s, 600K_s, 1900K_s (5000 steps, 0.5 fs, NVT ensemble)

**Additional AIMD Data:**
Pre-computed AIMD trajectories for other molecules (TTE, DMC, EA, DME, EGDME, PF6, and FSI) are publicly available at: https://doi.org/10.6084/m9.figshare.30487070. It should be noted that these data were generated using the LDA functional, which may constrain accuracy for systems with significant charge‑transfer or anisotropic interactions. Although we have demonstrated the reliability of the approach in the manuscript, users who prefer to employ the PBE functional can readily do so by replacing the exchange–correlation functional with PBE in both the AIMD and DFT calculations. 

#### 3.2 Configuration Collection
```bash
cd MLFF_dataset/
# Configure parameters in get_conf.sh
vim get_conf.sh  # Set temperature points and sampling parameters
sbatch get_conf.sh  # Extracts single-molecule configurations from AIMD trajectories in step 3.1 and saves them to the corresponding Conf_* directories while flagging abnormal molecules. Molecules whose bond lengths deviate by more than 20% from the reference values will be excluded from subsequent training. The reference values are set as the bond lengths of the two-step optimized EC molecule (stored in `./parameters/bond.molecule`). The deviation threshold can be adjusted via the parameter (`if abs(dist - self.bondLength[ib]) / self.bondLength[ib] > 0.2:`) within the `get_conf.py` script.
# If the simulation box sizes differ across AIMD trajectories at different temperatures, use the vi_box.py script to standardize the box dimensions of the extracted single-molecule configurations.
```

#### 3.3 SCF Calculations
```bash
cd ../1_SCF/

# SCF calculations
bash qsub_1.1_scf.sh

# Extract energies and forces  
bash qsub_1.2_get_dft_eng_force.sh

# Energy correction
bash qsub_2_energy_shift.sh
```

#### 3.4 DB Calculations and Model Fitting
```bash
# DB energies/forces calculation
cd ../2_dbmlff/
bash qsub.sh

# Model fitting
cd ../3_fit_mlff/
bash get_dataset.sh  # Prepares dataset，data_set
sbatch run.sh        # Fits MLFF model，Visualization results are located at `/MLFF/3_fit_mlff/fit_dir/eng_force_dataset.png`
```

**Quality Checks:**
Check the consistency between MLFF predictions and DFT references for energy and atomic forces in the visualization results at `eng_force_dataset.png`

**Data Cleaning Pipeline:**

1. **Input:** MOVEMENT files generated from AIMD simulations.
2. **Steps:**
   a) Run `MLFF_dataset/get_conf.sh` to extract single-molecule configurations from the MOVEMENT files at specified frame intervals, standardize them into `.config` format, and save them to the `Conf_*` directories. Concurrently, configurations with bond-length deviations exceeding 20% from the reference values in `./parameters/bond.molecule` are flagged as abnormal (recorded in `check_conf/*K_DFT_large_distortion.dat`). These abnormal molecules are subsequently excluded from the training dataset. A quantitative report assessing the amount of source data removed in this manner is located at `MLFF_dataset/removed_molecules_summary.dat`. Generally, datasets generated at higher temperatures tend to contain a greater number of molecular configurations flagged as abnormal.
   b) Run `1_SCF/qsub_1.2_get_dft_eng_force.sh` to collect the DFT energies and forces for all configurations from the dataset computed in the `1_SCF` folder, saving them to the `dft_eng_force.dat` file within the corresponding temperature directory under the current working path.
   c) Run `3_fit_mlff/get_dataset.sh` to gather all DFT energies and forces from the `dft_eng_force.dat` files, as well as the DB energies and forces for all configurations from the dataset computed in the `2_dbmlff` folder. The code automatically excludes the abnormal configurations flagged in step (a). The output is a clean, uniformly formatted dataset (located at `3_fit_mlff/data_set`) containing atomic positions, atomic forces, and atomic energies, ready for machine learning model training.
3. **Reproducibility:** This entire pipeline is scripted. Users can reproduce all steps by adjusting the parameters in `get_conf.sh`.


## Required Files for MD Simulation

### Force Field File
- `mol.1`: Automatically generated from previous steps
Note: For simulations of a multi-component system, a corresponding force field file is required for each additional molecule type. These files should follow the sequential naming convention mol.1, mol.2, mol.3, and so on.

### Control File (`MD.input`)
```
...
2, 100, 0.5, 300, 300         ! iMD, MDsteps, dt, T1, T2
...
```

We provide a template at `MD/template/MD.input`. For different simulation needs, generally only the parameters in the second line need to be modified, as shown above: ensemble, MD steps, time step, initial temperature, final temperature.

### Structure File (`atom.config`)
```
Total_Atoms  Molecule_Types  Atoms_per_Molecule  Molecule_Counts
[lattice vectors...]
[atomic coordinates...]
```
Note: The order of Atoms_per_Molecule must match the atom order in the force field file mol.*.

### Supporting Files
- Pseudopotentials: `*.nc.pbe.UPF.ionrhoR` (provided, located at `MD/template`)
- Submission script: `run_mpich.sh` (a reference template is provided, located at `MD/template`)   # The script uses software libraries and tools such as CUDA, NVHPC, MKL, NCCL, and MPI. The versions used have been specified in the earlier "Software Dependencies" section. Users only need to replace the paths of the software libraries and tools in `MD/md_test/run_mpich.sh` with their own system paths.

### Data Splitting, Model Validation, and Testing

The DBMLFF training data consist of single‑molecule DFT data for the target molecule, all of which are used as the training set. Our ultimate objective is to simulate multi‑molecular systems with DBMLFF. Therefore, we first perform preliminary validation of the force‑field performance through single‑molecule molecular dynamics simulations and run the analysis scripts described in the **Simulation Check and Analysis** section above. The final performance metrics are obtained by applying the DBMLFF model of the molecule to actual simulations of multi‑component electrolyte systems and comparing the results against DFT‑calculated reference values. For a concrete example, refer to the simulation setup and analysis in the `15tte_10ea_5lifsi` folder.
